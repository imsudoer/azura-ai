## About

`azura-ai` is an advanced Telegram **userbot** designed to behave like a real human being rather than an interactive bot or assistant. It possesses an internal mood, separate per-chat short and long memory, a persistent global memory, an opinion- and feeling-decay system, relationship proximity tiers, conflict dynamics, realistic diurnal sleep cycles with occasional nightly wakeups, sticker and GIF collections tagged by persona fit, and an autonomous tool-using agent architecture.

Built on Python 3.11+, kurigram, SQLAlchemy 2.x + SQLite (WAL mode) + `sqlite-vec` + FTS5, Pydantic v2, and the OpenAI SDK integrated with OpenAI-compatible endpoints.

> Primary Models: `claude-opus-4-6` for speaking voice and deep tool execution, `pplx-gemini-3.1-pro` for internal thinking (decision to reply, summaries, inner monologue, persona initialization, nightly dreams), and `text-embedding-3-small` / `pplx-embed` for vector embeddings (1536d).

## What Makes It Not Feel Like a Bot

- **Lives by a clock**: Sleeps according to the persona's configured `wake` and `sleep` hours, with rare, personality-driven nightly wakeups.
- **Attention queue**: Reads incoming messages according to human priority (`private -> group -> channel -> muted_private -> muted_group`), taking into account unread counts, interpersonal opinions, mood, and introversion.
- **Probabilistic reply engine**: "Read but chose not to answer", "ghost", or "react with an emoji" are real native outcomes based on proximity, mood, relationship score, and urgency.
- **Feelings and opinions with decay**: Tracks time-weighted emotional intensity per `(target, emotion)` and maintains aggregated opinion scores per user and per chat.
- **Conflict dynamics**: Dynamically chooses actions (de-escalate, stand ground, escalate, withdraw, passive-aggressive, or take sides) depending on conflict style and opponent aggression.
- **Human typing behavior**: Simulates human delays (pre-read pause, realistic typing speeds with pauses, after-send cooldown), occasional typos with self-correction (`*word`), and breaks long paragraphs into realistic short messages.
- **Personal sticker & GIF library**: Automatically discovers stickers from chats it participates in, tags them with mood/topic/persona-fit using an LLM, and sends them naturally in context.
- **Believable AFK behavior**: When browsing or searching the web, visibly goes offline with realistic reasons logged in its state.
- **Anti-detection safeguard**: Strips AI-typical phrasing and conversational markers before sending; maintains character consistency.
- **Personal journal & nightly dreams**: Maintains a first-person SQLite journal mirrored to markdown (`data/journal/YYYY-MM.md`). During sleep, a dream pass updates emotional memory and selects long-term memories.

## Quick Start (Windows / PowerShell)

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -e .[dev]

copy .env.example .env
# Edit .env and set your API keys

python -m azura.init_personality --interactive
python -m azura.login           # one-time interactive Telegram login
python -m azura.run
```

`azura.login` handles the initial Telegram phone/code/2FA authentication and writes `data/session.session`. After that, `azura.run` starts automatically.

## Configuration

Settings are managed via `.env`. Core parameters:

| Key | Default | Description |
|---|---|---|
| `TG_API_ID` / `TG_API_HASH` | — | Telegram API credentials (from my.telegram.org) |
| `TG_SESSION_NAME` | `session` | Session filename under `data/` |
| `OPERATOR_ID` | `your_telegram_id` | The Telegram user ID permitted to issue operator commands |
| `OPERATOR_SECRET` | `changeme` | Prefix passphrase required on operator DM commands |
| `ONLYSQ_API_KEY` | empty | API key for LLM provider |
| `MODEL_REPLY` | `claude-opus-4-6` | Primary conversational model |
| `MODEL_THINK` | `pplx-gemini-3.1-pro` | Reasoning and background thought model |
| `MODEL_EMBED` | `text-embedding-3-small` | Embedding model for semantic memory search |
| `EMBED_DIM` | `1536` | Vector dimensions for sqlite-vec |
| `HUMANIZE_MIN_REPLY_DELAY_S` | `2.5` | Minimum delay before answering |
| `HUMANIZE_MAX_REPLY_DELAY_S` | `900` | Maximum deliberate response latency |
| `HUMANIZE_TYPING_CHUNK_S` | `4.5` | Telegram typing indicator refresh interval |

## Operator Channel

Control commands sent to the userbot DM from `OPERATOR_ID` beginning with `OPERATOR_SECRET`:

| Command | Action |
|---|---|
| `status` | Snapshot of current mood, activity, and presence state |
| `sleep` | Force persona into asleep state |
| `wake` | Force persona online |
| `pause` | Pause message reading and replies (offline) |
| `resume` | Return to standard schedule |
| `journal [N]` | Print the last N journal entries (default 10) |

## Persona Immutability

When a persona is generated, `data/personality.json` is signed in `data/personality.lock` with two SHA256 digests. If modified manually, the engine refuses to start to prevent behavioral drift. To re-roll: remove both files and run `init_personality`.
